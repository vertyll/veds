# Glossary

Terms the documentation uses, the standard each one comes from, and where it is explained.

| Term                        | Meaning                                                                                                              | Standard                                                                                                                                           | Explained in                                                                                                                                                                              |
|-----------------------------|----------------------------------------------------------------------------------------------------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Authorization code flow     | Sign-in by redirecting to Keycloak and exchanging the returned code on the server.                                   | [RFC 6749](https://www.rfc-editor.org/rfc/rfc6749#section-4.1) §4.1                                                                                | [Keycloak Configuration: Authentication Flow — Token Handler (BFF) with Authorization Code + PKCE](docs/keycloak.md#authentication-flow--token-handler-bff-with-authorization-code--pkce) |
| Avro, Schema Registry       | The binary event format and the registry that checks every schema change for compatibility.                          | [Apache Avro](https://avro.apache.org/docs/)                                                                                                       | [Event Catalog: Conventions that hold for all of them](docs/events.md#conventions-that-hold-for-all-of-them)                                                                              |
| BFF (token handler)         | The API gateway signs the user in and keeps the tokens; the browser holds only a cookie.                             | —                                                                                                                                                  | [Keycloak Configuration: Authentication Flow — Token Handler (BFF) with Authorization Code + PKCE](docs/keycloak.md#authentication-flow--token-handler-bff-with-authorization-code--pkce) |
| Bounded context             | One service's domain, with its own model, database and language.                                                     | —                                                                                                                                                  | [Architecture: Domain-Driven Design (DDD)](docs/architecture.md#domain-driven-design-ddd)                                                                                                 |
| Compensation topic          | The topic a service listens on to undo its part of a saga.                                                           | —                                                                                                                                                  | [Eventual Consistency: Outbox, Inbox and Sagas: Compensation Topic](docs/eventual-consistency.md#compensation-topic)                                                                      |
| CQRS                        | Separate ports for reading and writing; the read side never loads an aggregate.                                      | —                                                                                                                                                  | [CQRS](docs/cqrs.md)                                                                                                                                                                      |
| Domain event, command       | An event states what happened and belongs to its producer; a command asks for something and belongs to its consumer. | —                                                                                                                                                  | [Event Catalog: Ownership rule](docs/events.md#ownership-rule)                                                                                                                            |
| ETag, `If-Match`            | Version of a resource, and the condition a write carries so a stale edit is refused.                                 | [RFC 9110](https://www.rfc-editor.org/rfc/rfc9110#section-8.8.3) §8.8.3, [RFC 9110](https://www.rfc-editor.org/rfc/rfc9110#section-13.1.1) §13.1.1 | [Optimistic Locking & Concurrency Control: Error Semantics at the API Layer](docs/concurrency.md#error-semantics-at-the-api-layer)                                                        |
| Hexagonal architecture      | Ports in the application layer, adapters in infrastructure, dependencies pointing inward.                            | —                                                                                                                                                  | [Hexagonal Layering: The rule](docs/hexagonal-layering.md#the-rule)                                                                                                                       |
| ICU MessageFormat           | The message syntax, with plural rules for Polish.                                                                    | [ICU MessageFormat](https://unicode-org.github.io/icu/userguide/format_parse/messages/)                                                            | [Translations: ICU, and why not java.text.MessageFormat](docs/translations.md#icu-and-why-not-javatextmessageformat)                                                                      |
| ID token                    | Token describing who signed in.                                                                                      | [OpenID Connect Core 1.0](https://openid.net/specs/openid-connect-core-1_0.html)                                                                   | [Keycloak Configuration: Authentication Flow — Token Handler (BFF) with Authorization Code + PKCE](docs/keycloak.md#authentication-flow--token-handler-bff-with-authorization-code--pkce) |
| Inbox (idempotent receiver) | Records every consumed event, so a redelivery changes nothing.                                                       | —                                                                                                                                                  | [Eventual Consistency: Outbox, Inbox and Sagas: Inbox — Idempotent Receiver](docs/eventual-consistency.md#inbox--idempotent-receiver)                                                     |
| JWT, JWKS                   | The signed token every service verifies, and Keycloak's published keys it is verified against.                       | [RFC 7519](https://www.rfc-editor.org/rfc/rfc7519), [RFC 7517](https://www.rfc-editor.org/rfc/rfc7517)                                             | [Keycloak Configuration: Tokens are accepted only by the component they were issued for](docs/keycloak.md#tokens-are-accepted-only-by-the-component-they-were-issued-for)                 |
| Message key                 | A key of the translation catalog sent instead of prose; the client renders it.                                       | —                                                                                                                                                  | [Translations: Two tracks: who renders the text](docs/translations.md#two-tracks-who-renders-the-text)                                                                                    |
| Permission scope            | What a permission applies to: the whole system or one project.                                                       | —                                                                                                                                                  | [Authorization: Scope](docs/authorization.md#scope)                                                                                                                                       |
| PKCE                        | A one-time secret that ties the returned code to the browser that started the sign-in.                               | [RFC 7636](https://www.rfc-editor.org/rfc/rfc7636)                                                                                                 | [Keycloak Configuration: Authentication Flow — Token Handler (BFF) with Authorization Code + PKCE](docs/keycloak.md#authentication-flow--token-handler-bff-with-authorization-code--pkce) |
| Pre-signed URL              | A time-limited storage URL that lets the browser upload or download one object directly.                             | [Amazon S3 API](https://docs.aws.amazon.com/AmazonS3/latest/API/Welcome.html)                                                                      | [Files: The exchange](docs/files.md#the-exchange)                                                                                                                                         |
| Problem document            | The JSON body of every refusal, carrying a message key.                                                              | [RFC 9457](https://www.rfc-editor.org/rfc/rfc9457)                                                                                                 | [Testing: Why the problem document is pinned twice](docs/testing.md#why-the-problem-document-is-pinned-twice)                                                                             |
| Projection                  | A service's local, read-only copy of data another service owns, kept current by events.                              | —                                                                                                                                                  | [Authorization: How a decision is made](docs/authorization.md#how-a-decision-is-made)                                                                                                     |
| Saga                        | A business process across services, with a compensating step for each step that can fail.                            | —                                                                                                                                                  | [Eventual Consistency: Outbox, Inbox and Sagas: Saga Engine](docs/eventual-consistency.md#saga-engine)                                                                                    |
| `SameSite` cookie           | `VEDS_SESSION` is `Strict`, so it never travels on a cross-site request.                                             | [RFC 6265bis](https://datatracker.ietf.org/doc/draft-ietf-httpbis-rfc6265bis/) (draft)                                                             | [Keycloak Configuration: Implementation notes](docs/keycloak.md#implementation-notes)                                                                                                     |
| Single-flight refresh       | One refresh per refresh token, across gateway replicas.                                                              | —                                                                                                                                                  | [Keycloak Configuration: Refreshing a token is single-flight, per refresh token](docs/keycloak.md#refreshing-a-token-is-single-flight-per-refresh-token)                                  |
| Token exchange              | The gateway trades the person's token for one whose only audience is the target service.                             | [RFC 8693](https://www.rfc-editor.org/rfc/rfc8693)                                                                                                 | [Keycloak Configuration: Each service gets a token for itself alone](docs/keycloak.md#each-service-gets-a-token-for-itself-alone)                                                         |
| Transactional outbox        | Events written in the same transaction as the state they describe, then published.                                   | —                                                                                                                                                  | [Eventual Consistency: Outbox, Inbox and Sagas: Transactional Outbox](docs/eventual-consistency.md#transactional-outbox)                                                                  |
